# Retention partition-drop benchmark

Этот benchmark фиксирует фактическое время обработки retention partitions и
переводит его в нормализованный показатель `partitions_per_second`. Флаг
`dry_run` сохраняется рядом с результатом, чтобы планирование удаления нельзя
было случайно сравнить с реальным `DROP` как с одинаковой операцией.

## Как проводить измерение

1. Выбрать конкретный cutoff и перечислить partitions, которые worker должен
   обработать.
2. Зафиксировать PostgreSQL version, размер каждой partition, индексы, тип
   диска и число concurrent workers.
3. Измерить wall-clock время операции в миллисекундах и передать число
   partitions, elapsed milliseconds и режим в
   `retention_benchmark::measure_retention`.
4. Сохранить результат вместе с окружением и повторить измерение минимум три
   раза; для отчёта использовать медиану и отдельно указать максимум.

## Интерпретация

Результат `None` означает некорректные входные данные (ноль partitions или
нулевое время). Это защита от деления на ноль и фиктивного throughput.
`dry_run = true` показывает только стоимость построения плана; такой замер не
является SLA для destructive `DROP` и не заменяет проверку восстановления.

Текущий helper нормализует уже измеренные значения и не выполняет SQL сам.
Поэтому production-замер должен выполняться на staging-копии с тем же объёмом
данных, а не выводиться из unit-теста.
